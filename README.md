# Лабораторная работа №4

Матрицы имеют тип `double` и хранятся построчно. Все варианты получают одинаковые воспроизводимые входные данные.

## Компиляция с GCC

```sh
gcc -O3 -std=c11 -Wall -Wextra -fopenmp matmul.c -o matmul
```

## Запуск

```sh
./matmul N block threads version
```

- `N` — размер квадратной матрицы, положительное целое число.
- `block` — размер блока, положительное целое число; используется в `blocked_omp`.
- `threads` — запрошенное число потоков; последовательные версии используют один поток.
- `version` — `ijk_seq`, `ijk_omp`, `ikj_seq`, `ikj_omp` или `blocked_omp`.

Например:

```sh
./matmul 1024 32 8 blocked_omp
./matmul 1024 32 1 ijk_seq
./matmul 1024 32 8 ijk_omp
./matmul 1024 32 1 ikj_seq
./matmul 1024 32 8 ikj_omp
```

Программа выполняет один прогрев и пять измерений; выводит медиану времени в секундах, фактическое число потоков, максимальную абсолютную ошибку, число несовпадений и пять измеренных времён в порядке возрастания. Перед каждым запуском результат обнуляется. Выделение памяти, заполнение, обнуление и проверка не входят в измеряемое время.

Каждый результат, включая прогрев, сравнивается с `ijk_seq`. Условие проверки каждого элемента: `abs(C - reference) <= 1e-9 * (1 + abs(reference))`. При ошибке проверки программа завершится с ненулевым кодом.

Для отчёта использованы N = 128, 256, 512, 1024, потоки 1, 2, 4, 8, 16 и блоки 16, 32, 64. Основное сравнение размеров проведено с 8 потоками и блоком 32. Ускорения `ijk_omp` и `ikj_omp` считаются относительно своих последовательных версий. Отношение времени `ikj_seq` к `blocked_omp` включает одновременно эффекты параллелизма и блочной обработки.

Замеры отчёта выполнены на Apple M4 с Apple Clang 17.0.0, LLVM libomp 23.1.2 и оптимизацией `-O3`, без `fast-math`. Команда выше предназначена для GCC с поддержкой OpenMP; встроенный в macOS `gcc` обычно является Apple Clang и требует отдельного подключения libomp.
